**Цель:** написать методы своего модуля и научиться делать атомарные коммиты.

**Что сдаём:** Pull Request с методами своего модуля, ревью соседа, слияние с веткой напарника.

### Шаг 1. Узнай свой модуль

На паре распределяем модули. Список всех модулей и их коротких имён — в [главном README](../../README.md#модули).

### Шаг 2. Создай свою ветку

Имя ветки: `модуль-ваши_опознавательные_знаки`.

```bash
git switch main
git switch -c cart-ivanova
```

Новую ветку каждую пару создавать не нужно, пока работаем только в ней.

### Шаг 3. Прочитай свой файл

Что должен делать каждый метод, написано в комментарии над ним. Сейчас внутри каждого метода стоит `// TODO` и «заглушка» — `return 0;`, `return -1;` и т. п. Её нужно заменить на настоящий код.

### Шаг 4. Пишем методы по одному

1. Удали `// TODO` и заглушку, напиши код.
2. Запусти `main` своего модуля. Все проверки этого метода должны стать `OK`.
3. Посмотри, что изменилось, и сделай коммит, например:

```bash
git diff
git add src/main/java/delivery/Cart.java
git commit -m "cart: add cartTotal"
```

> Некоторые проверки показывают `OK` ещё до того, как что-то поменялось. Это совпадение: заглушка случайно вернула правильный ответ (например, 0 для пустой корзины). Метод всё равно нужно написать.

## Как хранятся данные

Все данные лежат в `DeliveryData.java` в виде **параллельных массивов**: i-й элемент каждого массива относится к одному объекту.

- Всё про блюдо номер 2: `dishNames[2]`, `dishPrices[2]`, `dishRestaurant[2]`...
- **Деньги в копейках:** `34000` = 340,00 ₽.
- **Время в минутах от полуночи:** `600` = 10:00, `1320` = 22:00.
- **Город** — сетка клеток от (0, 0) до (10, 10).

Обращаться к данным так: `DeliveryData.dishPrices[i]`.

## Правила по коду

- Можно: `if`, циклы, свои вспомогательные методы, массивы, `length`, `charAt`, `equals`, `Math.*`.
- Нельзя: `Arrays.sort`, коллекции (`ArrayList`, `HashSet`...), стримы, рекурсию.
- Метод **возвращает** результат и ничего не печатает (`System.out.println` внутри метода не нужен).

## Интеграция

Метод из блока интеграция использует метод напарника из другого модуля.

| Свой модуль | Берём метод у |
|---|---|
| Меню | Время (`Time.isOpen`) |
| Корзина, Отзывы | Меню (`Menu.findDish`, `Menu.cheapestInRestaurant`) |
| Промокоды, Доставка | Корзина (`Cart.cartTotal`) |
| Время, Курьеры, Маршрут | Доставка (`Delivery.distance`) |
| Аналитика | Отзывы (`Reviews.bestRestaurant`) |

Пока метод напарника — заглушка, интеграция будет `FAIL`. Чтобы получить его настоящий код, нужно влить ветку напарника в свою:

Вытягиваем свежие изменения из репозитория, и конкретно нужной ветки:

```bash
git fetch
git switch ветка-напарника
git pull
```

Сливаем свою ветку с веткой напарника, в итоге в вашей ветке окажется весь код напарника:

```bash
git switch своя-ветка
git merge ветка-напарника --no-edit
git push
```

Список всех веток можно получить как `git branch -r`.

Допишите свой метод интеграции, проверьте, что проверки в блоке «Интеграция» стали `OK`, сделайте коммит `git commit -m "Описание сделанных изменений"` и `git push`.

## Правила ревью 

Проверяем PR **следующего** модуля по кругу:

Меню → Корзина → Промокоды → Доставка → Время → Курьеры → Маршрут → Отзывы → Аналитика → Меню

(Меню — смотрит Корзину, Аналитика — Меню и т.д.). Если следующий модуль никому не достался, берите через один.

Как оставить комментарий: Pull Requests → выбрать нужный → вкладка **Files changed** → наведи мышь на строку → синий **+** → напиши текст → **Add single comment**.

Оставь хотя бы **3 комментария к строкам кода**, можно:

1. на каких данных метод сломается (пустой массив, 0, граница диапазона, отрицательное число);
2. что непонятно или лишнее;
3. что понравилось.

## Правки после ревью

Прочитай комментарии к своему PR. Исправь код, сделай коммит и `git push` — PR обновится сам. С чем не согласен, ответь в комментарии, почему.
